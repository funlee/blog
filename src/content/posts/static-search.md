在构建时生成索引，在浏览器里完成查询。不需要服务器，也可以快速找到一段记忆。

## 从一个小问题开始

我们常常等到准备充分才开始，但真正的理解，往往发生在动手之后。先做一个足够小的版本，把想法放到真实的环境里观察，再一点点调整。

写博客也是如此。不必急着给每一篇文章一个完美的结论。记录问题、尝试和新的发现，本身就有价值。

## 把复杂的事情变简单

好的工具应该让注意力回到内容。这个部落格使用本地 Markdown 文件保存文章，构建时生成页面，阅读时无需等待内容接口。

- **内容优先**：清楚的标题、舒适的行距，以及适当的留白。
- **保持轻盈**：只引入真正需要的交互。
- **持续积累**：让每一次小小的探索，都有一个可以回来的地方。

### 一个可以复用的例子

```ts
const thoughts = ["观察", "尝试", "记录"];

function keepLearning(items: string[]) {
  return items.map((item, index) => ({
    step: index + 1,
    action: item,
  }));
}

console.log(keepLearning(thoughts));
```

代码可以复制，长行在代码区域内部滚动。文章目录会随着阅读进度标记当前章节。

## 记录与反馈

| 阶段 | 关注的事情 | 留下的记录 |
| --- | --- | --- |
| 开始 | 我想解决什么问题 | 一句话描述 |
| 尝试 | 哪些方法值得验证 | 过程与代码 |
| 回顾 | 下一次能做得更好吗 | 收获与改进 |

> 不需要每一天都前进很远。重要的是，保持好奇，也保持耐心。

## 写在最后

这只是一个开始。以后再回头看，也许会发现，现在认真写下的这些小事，正是成长最清晰的痕迹。
