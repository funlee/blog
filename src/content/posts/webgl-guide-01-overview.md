> 本文整理自 2019 年的《WebGL 编程指南》阅读笔记。发布日期采用印象笔记的创建时间；2026 年 10 月迁移时补充解释并修正示例，统一使用 WebGL 1 / GLSL ES 1.00。

学习 WebGL 时，最容易困惑的地方不是某一个 API，而是代码为什么同时出现在 HTML、JavaScript 和着色器三个地方。它们各自负责什么？一组坐标又是怎样变成屏幕上的图像的？先把这条路径理清，再读绘制和变换的示例会轻松很多。

## WebGL 与 OpenGL ES 的关系

WebGL 是浏览器提供的图形 API，可以在 `<canvas>` 上进行硬件加速绘制。原笔记把它称为“Web 版的 OpenGL”，这是便于入门的类比，但两者不能直接画等号：WebGL 1 主要基于 OpenGL ES 2.0，并加入了适合浏览器环境的约束。

OpenGL 是图形接口标准；OpenGL ES 面向嵌入式等环境；WebGL 则把相关能力带入 Web。它们不是三套互不相干的工具，也不意味着桌面 OpenGL 程序可以原样复制到浏览器中。

本系列使用 WebGL 1 和 GLSL ES 1.00。后文的 `attribute`、`varying`、`gl_FragColor`、`texture2D` 都处在这一语法背景下。如果主动改用 WebGL 2 和 GLSL ES 3.00，需要同步调整着色器，不能只替换上下文名称。

## 一个程序为什么需要三种语言

| 部分 | 主要职责 | 典型内容 |
| --- | --- | --- |
| HTML | 提供画布与页面结构 | `<canvas>`、脚本引用 |
| JavaScript | 准备数据、设置状态、发出绘制指令 | 顶点数组、缓冲区、矩阵、事件和动画循环 |
| GLSL ES | 描述着色器阶段的计算 | 计算顶点位置、计算片元颜色 |

GLSL ES 是用于着色器的语言，与 JavaScript 是两种不同的语言。着色器源码虽然经常写在 JavaScript 字符串里，但字符串最终会交给 WebGL 编译和链接，而不是由 JavaScript 引擎当普通函数执行。

原笔记提到的“可编程着色器”，正是这里的关键：应用不只提交固定形状和颜色，还能够描述顶点位置与片元颜色如何计算。

## 从顶点数据到画面

可以先按下面的顺序理解一次绘制：

1. JavaScript 准备顶点位置、颜色、纹理坐标等数据。
2. 将数据上传到缓冲区，并告诉 WebGL 每个属性如何读取。
3. 顶点着色器计算顶点的裁剪空间位置。
4. 图元装配把顶点组成点、线或三角形，随后经过裁剪与光栅化。
5. 片元着色器计算候选片元的颜色。
6. 通过深度测试、混合等后续处理后，结果写入绘制目标。

这里的片元可以先近似理解为“等待参与像素计算的数据”，但它不严格等于最终屏幕上的一个像素。同一个像素可能对应多个候选片元；有些片元会被丢弃，也可能经过混合才得到最终颜色。

这条路径也提示了排查思路：位置不对时看顶点和矩阵，颜色不对时看属性传递与片元着色器，整块画布不显示时则从上下文、着色器编译、缓冲区绑定和绘制调用逐层检查。

## 一点 GLSL ES 预备知识

在 WebGL 1 中，一个绘制程序通常包含顶点着色器与片元着色器。`gl_Position` 是顶点着色器输出的位置；`gl_FragColor` 是片元着色器输出的颜色。它们不是可以随意更换名字的普通变量。

GLSL ES 有自己的类型系统，例如浮点数 `float`、向量 `vec2` / `vec3` / `vec4` 和矩阵 `mat4`。书中的 `10.0` 也并非单纯的书写风格：在相应浮点表达式中，应按 GLSL ES 的类型规则使用浮点字面量。

后续会逐步接触三类数据通道：`attribute` 接收逐顶点属性；`uniform` 提供一次绘制中共享的参数；`varying` 将顶点阶段的输出交给片元阶段，并在光栅化时参与插值。

## 如何安排学习顺序

先让画布显示一个点，再尝试一次绘制多个顶点。这一步会引入缓冲区、类型化数组和图元类型。随后再学习平移、旋转、缩放，把单个变换组合成矩阵，并用时间驱动动画。

颜色与纹理会把关注点从“顶点在哪里”扩展到“表面是什么样”。进入三维之后，再区分模型矩阵、视图矩阵、投影矩阵和深度测试的职责，就能逐渐建立完整的渲染流程。
